# trade-signal-agent

سرویس پایتونی که بازار کریپتو را با روش بالا به پایینِ `docs/STRATEGY.md` بررسی می‌کند و سیگنال‌های فیوچرز (و ایده‌های هفتگی HOLD اسپات) را به فارسی در تلگرام می‌فرستد.

- **هزینه‌ی اجرا صفر:** فقط APIهای عمومی و رایگان (صرافی از طریق `ccxt`، CoinGecko، Telegram Bot API). هیچ LLM یا API پولی در زمان اجرا استفاده نمی‌شود.
- **قطعی و قابل بک‌تست:** همه‌ی عددها در `config.yaml` است و هر سیگنال از روی کندل‌های ذخیره‌شده و تنظیمات قابل بازسازی است.
- **اول GitHub Actions، بعد سرور:** همان کد؛ Actions فقط زمان‌بند است.

> ⚠️ **این ابزار مشاوره‌ی مالی نیست.** نتیجه‌ی بک‌تست یک‌ساله‌ی استراتژی فعلی (بعد از کارمزد، اسلیپیج و فاندینگ) منفی بوده است؛ جزئیات در `docs/BACKTEST.md`. پیشنهاد: فعلاً فقط **پیپرترید** (دریافت پیام بدون معامله‌ی واقعی) تا وقتی نسخه‌ای از تنظیمات در بک‌تست و دوره‌ی holdout مثبت شود.

## راه‌اندازی روی GitHub Actions

### ۱. ساخت ربات تلگرام (BotFather)
1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید و دستور `/newbot` را بفرستید.
2. یک نام و یک نام‌کاربری که به `bot` ختم شود انتخاب کنید.
3. BotFather یک **توکن** مثل `123456789:AA...` می‌دهد. این همان `TELEGRAM_BOT_TOKEN` است. آن را جایی منتشر نکنید.

### ۲. پیدا کردن chat id
- **چت خصوصی:** اول به ربات خودتان یک پیام (مثلاً `/start`) بفرستید. بعد در مرورگر این آدرس را باز کنید (به‌جای `<TOKEN>` توکن خودتان):
  `https://api.telegram.org/bot<TOKEN>/getUpdates`
  در خروجی، مقدار `"chat":{"id": ...}` همان `TELEGRAM_CHAT_ID` است.
- **کانال:** ربات را **ادمین** کانال کنید، یک پیام در کانال بگذارید و همان آدرس `getUpdates` را باز کنید. شناسه‌ی کانال با `-100` شروع می‌شود (مثلاً `-1001234567890`).
- **گروه:** ربات را به گروه اضافه کنید، در گروه پیام بدهید و از `getUpdates` شناسه‌ی منفی گروه را بردارید.

### ۳. کلید رایگان CoinGecko (اختیاری ولی توصیه‌شده)
در [CoinGecko API](https://www.coingecko.com/en/api/pricing) یک حساب رایگان (Demo) بسازید و کلید را بردارید. بدون کلید هم کار می‌کند ولی کندتر است (محدودیت درخواست).

### ۴. تعریف Secretها در GitHub
در مخزن: **Settings → Secrets and variables → Actions → New repository secret** و این سه را بسازید:

| نام | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن BotFather |
| `TELEGRAM_CHAT_ID` | شناسه‌ی چت/کانال/گروه |
| `COINGECKO_API_KEY` | کلید Demo کوین‌گکو (اختیاری) |

اگر توکن یا chat id تعریف نشود، برنامه خطا نمی‌دهد و پیام‌ها را فقط در لاگ اجرا چاپ می‌کند (حالت **dry-run**). برای شروع می‌توانید همین‌طور چند روز لاگ‌ها را ببینید.

### ۵. فعال کردن Actions
1. کدها باید روی **شاخه‌ی پیش‌فرض** (مثلاً `main`) باشند؛ GitHub زمان‌بندی (cron) را فقط از شاخه‌ی پیش‌فرض اجرا می‌کند.
2. **Settings → Actions → General → Workflow permissions** را روی **Read and write permissions** بگذارید. وضعیت برنامه (دیتابیس SQLite) در شاخه‌ی جداگانه‌ی `data` ذخیره می‌شود و برای نوشتن در آن این دسترسی لازم است.
3. در تب **Actions**، workflow به نام **agent** را باز کنید و **Run workflow** بزنید. اجرای اول کمی طول می‌کشد (حدود ۱۰ دقیقه) چون تاریخچه‌ی یک‌ساله‌ی دامیننس را می‌سازد. از آن به بعد هر ۱۵ دقیقه خودکار اجرا می‌شود.
4. workflow **check-sources** بررسی می‌کند کدام صرافی‌ها و منابع از سرورهای GitHub جواب می‌دهند (سرورها در آمریکا هستند و Binance/Bybit جواب نمی‌دهند؛ OKX پیش‌فرض است).

> GitHub در مخزن عمومی، اگر ۶۰ روز هیچ فعالیتی در مخزن نباشد، زمان‌بندی را غیرفعال می‌کند. ذخیره‌ی وضعیت در شاخه‌ی `data` خودش فعالیت حساب می‌شود؛ اگر زمان‌بندی متوقف شد، از تب Actions دوباره فعالش کنید.

## زمان‌بندی

workflow **agent** هر ۱۵ دقیقه دستور `run-scheduled` را اجرا می‌کند. این دستور خودش تشخیص می‌دهد چه کاری سررسید شده، پس اگر GitHub یک اجرا را با تأخیر یا جا بیندازد، اجرای بعدی جبران می‌کند:

| کار | دستور | زمان |
|---|---|---|
| مدیریت سیگنال‌های باز (ورود، TP، حد ضرر، انقضا) | `run-15m` | هر اجرا (۱۵ دقیقه) |
| لایه ۱ تا ۵: رژیم، کوین‌های اصلی، اسکنرها، جفت‌ها، گلچین | `run-4h` | بعد از بسته شدن هر کندل 4H |
| لایه ۶: امتیاز تکنیکال گلچین و صدور سیگنال | `run-1h` | بعد از بسته شدن هر کندل 1H |
| گزارش روزانه (رژیم، BTC/ETH/ETHBTC، واچ‌لیست) و کوین‌های تازه‌ی HOLD | `run-daily` | هر روز ۰۰:۰۰ UTC |
| گزارش هفتگی HOLD اسپات | `run-weekly` | دوشنبه ۰۰:۰۰ UTC (کلوز هفتگی) |

- **مخزن خصوصی:** GitHub برای مخزن خصوصی ماهانه ۲۰۰۰ دقیقه‌ی رایگان می‌دهد که برای اجرای ۱۵ دقیقه‌ای کافی نیست. در فایل `.github/workflows/agent.yml` خط cron را به `"*/30 * * * *"` تغییر دهید (و در `config.yaml` مقدار `schedule.trigger_check_minutes` را ۳۰ کنید).
- برای اجرای دستی یک کار خاص: Actions → agent → Run workflow و در فیلد `only` مثلاً `run-4h,run-1h` بنویسید.

## پیام‌ها
هر کوین فقط **یک خط** است، همیشه با همین ترتیب، و فقط **یک امتیاز** دیده می‌شود: امتیاز نهایی تحلیل تکنیکال (لایه ۶):

```
🟢 SOLUSDT | LONG | امتیاز 82 | ورود 152.30 | SL 148.90 | TP1 158.10 | TP2 163.20 | پولبک به حمایت 4H + انگالف 1H
```

- 🟢 سیگنال (همه‌ی شرط‌های اجباری برقرار، رده A/B) و 🟡 Watch (نزدیک ستاپ، هنوز تأیید نشده).
- **سیگنال جدید:** خط کوین + یک خط «ریسک 1٪ | حجم X٪ موجودی | لوریج Nx».
- **Watch:** همان خط با 🟡؛ فقط وقتی برنامه‌ی معامله (ورود/SL/TP) وجود دارد، برای هر کوین حداکثر یک‌بار در ۲۴ ساعت.
- **گزارش روزانه:** دو خط سرتیتر (رژیم و «سیگنال باز: X از 5»)، یک خط برای هر کوینی که سیگنال یا Watch دارد (به ترتیب امتیاز)، و کوین‌های گلچین بدون ستاپ فقط با نام. 🟢 در گزارش روزانه یعنی سیگنالی که واقعاً ارسال شده و باز است؛ ستاپ A/B که به خاطر سقف یا همبستگی ارسال نشده با 🟡 و «صادر نشد» می‌آید.
- پیام‌هایی که امتیاز دارند (سیگنال، Watch، گزارش روزانه) در پایان یک پاراگراف «ℹ️ امتیاز» دارند که بخش‌های امتیاز، شرط‌های اجباری و بازه‌های رده را توضیح می‌دهد؛ عددها مستقیم از `config.yaml` خوانده می‌شوند.
- **به‌روزرسانی سیگنال** (بدون امتیاز، هر کدام یک خط): `✅ SOLUSDT | ورود فعال شد | 152.30`، `🎯 SOLUSDT | TP1 | +2.1R | SL به ورود`، `🎯 SOLUSDT | TP2 | +3.2R | تریل روی MA25 4H`، `🛑 SOLUSDT | SL | -1.0R`، و همین‌طور خروج نهایی، حد ضرر در ورود، انقضا و لغو.
- **ترمز ضرر:** بعد از ۳ حد ضرر پیاپی تا کلوز روزانه‌ی بعدی سیگنال جدید صادر نمی‌شود.
- **گزارش هفتگی HOLD** بدون تغییر.
- **گزارش عملکرد واقعی (هفتگی، همراه گزارش HOLD):** تعداد معاملات بسته‌شده، نرخ برد و مجموع R در ۷ روز اخیر و از ابتدا، به تفکیک رده، از روی سیگنال‌های ذخیره‌شده. R بدون کارمزد و اسلیپیج است.

## تنظیمات (`config.yaml`)
همه‌ی آستانه‌ها، وزن‌ها و دوره‌ها در `config.yaml` است و تغییرشان نیاز به تغییر کد ندارد. چند کلید مهم:

| کلید | کاربرد |
|---|---|
| `exchange.primary` / `exchange.fallbacks` | صرافی منبع کندل و ترتیب پشتیبان‌ها |
| `universe.top_n`, `universe.min_volume_24h_usd` | جامعه‌ی آماری و فیلتر نقدینگی |
| `grades` | مرز رده‌های A / B / Watch و A+ |
| `trade.base_risk_pct`, `trade.leverage_cap` | ریسک پایه‌ی هر معامله و سقف لوریج |
| `lifecycle.max_active` | سقف سیگنال‌های فعال هم‌زمان |
| `trade.stop_mode`, `trade.min_stop_pct`, `trade.tp1_max_r`, `lifecycle.cooldown_after_stop_h` | چهار تغییر آزمایشی بک‌تست؛ به‌طور پیش‌فرض **خاموش** هستند و رفتار همان STRATEGY.md است |
| `trade.entry_mode` (`level` / `confirm_4h`) | ورود روی سطح (پیش‌فرض) یا ورود فقط بعد از کلوز تأییدی 4H پس از لمس منطقه‌ی ورود؛ SL و TP از قیمت واقعی ورود دوباره حساب می‌شوند |
| `trade.stop_mode: atr`, `trade.atr_stop_mult` | حد ضرر = ورود ∓ ۱.۵×ATR(4H)؛ پیش‌فرض همان `level` است |
| `trade.tp1_mode` (`level` / `fixed_r`), `trade.tp1_fixed_r` | TP1 روی اولین سطح مخالف (پیش‌فرض) یا ثابت 2R و TP2 در 3R بدون رد شدن به‌خاطر R:R سطح |

تصمیم‌هایی که در جاهای مبهم استراتژی گرفته شده، همه در `docs/DECISIONS.md` آمده است.

> **تنظیمات فعلی اجرای زنده (پیپرترید):** کلید `live.variant` در `config.yaml` یکی از نسخه‌های `backtest.variants` را روی تنظیمات اصلی اعمال می‌کند، فقط برای دستورهای `run-*`. الان `atr_2r_a_only` است: حد ضرر ۱.۵ ATR(4H)، TP1 ثابت ۲R، TP2 برابر ۳R و فقط سیگنال رده A (ستاپ‌های رده B به‌صورت Watch می‌آیند). برای برگشت به STRATEGY.md مقدار آن را خالی کنید. بک‌تست و تست‌ها همیشه تنظیمات اصلی را می‌خوانند.

## بک‌تست
- workflow **backtest** (در تب Actions → Run workflow) تاریخچه‌ی یک سال را دانلود می‌کند، همه‌ی نسخه‌های تنظیمات (`backtest.variants`) را موازی اجرا می‌کند و گزارش مقایسه را می‌سازد. سه ماه آخر به‌عنوان **holdout** جدا گزارش می‌شود و برای انتخاب استفاده نمی‌شود.
- نتیجه در خروجی همان اجرا (Summary و artifact) است و نسخه‌ی تأییدشده در `docs/BACKTEST.md` قرار می‌گیرد.
- اجرای محلی:
  ```bash
  trade-agent backtest --fetch            # دانلود و اجرای تنظیمات فعلی
  trade-agent backtest --variant combined --json combined.json
  trade-agent backtest-compare *.json --out docs/BACKTEST.md
  ```

## اجرا روی سرور (VPS)
همان کد، با cron سرور به‌جای GitHub:

```bash
git clone <آدرس مخزن> /opt/trade && cd /opt/trade
python3 -m venv .venv && .venv/bin/pip install -e .
cat > .env <<'ENV'
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_ID=...
export COINGECKO_API_KEY=...
ENV
. ./.env && .venv/bin/trade-agent check-sources     # کدام منابع جواب می‌دهند
```

روی سرور دیتابیس یک فایل محلی است (`storage.backend: local` و مسیر `data/state.db`). با `crontab -e` این خط را اضافه کنید:

```cron
*/15 * * * * cd /opt/trade && . ./.env && .venv/bin/trade-agent run-scheduled >> agent.log 2>&1
```

برای انتقال وضعیت از GitHub به سرور، فایل `state.db.gz` را از شاخه‌ی `data` بردارید، از حالت فشرده خارج کنید و در `data/state.db` بگذارید.

## دستورها

| دستور | کار |
|---|---|
| `trade-agent check-sources` | تست صرافی‌ها، CoinGecko و تلگرام |
| `trade-agent run-scheduled` | اجرای هر کاری که سررسید شده (برای cron) |
| `trade-agent run-4h` / `run-1h` / `run-15m` / `run-daily` / `run-weekly` | اجرای یک کار به‌تنهایی |
| `trade-agent backtest` / `backtest-compare` | بک‌تست و مقایسه‌ی نسخه‌ها |

## توسعه
```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest -q
```

ساختار کد در `src/agent/`: `data/` (منابع داده)، `indicators/` و `analysis/` (اندیکاتورها، ساختار، فاز، سایکل‌ها، الگوها)، `layers/` (لایه‌های ۱ تا ۶ و ساخت معامله)، `hold/` (اسکنر HOLD)، `signals/` (چرخه‌ی عمر سیگنال)، `notify/` (قالب فارسی و ارسال تلگرام)، `store/` (SQLite و ذخیره‌سازی)، `backtest/` (بک‌تست).
